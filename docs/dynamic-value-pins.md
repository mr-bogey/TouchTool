# 动态类型能力说明（任意值 PinAny + 六节点）

> 分支：`feature/dynamic-value-pins`｜基线：上游 master `669706c`
> 性质：**纯增量**——新增 7 个文件 + 注册表加行，旧节点/旧容器代码零改动，旧 `.tt` 任务零迁移。

## 1. 动机

现有变量/针脚为静态强类型：声明后类型固定，列表元素与字典键值类型固定，无法表达「变量随运行换类型、列表套列表、字典混合键值、多维数组、无 schema 组对象」；旧 JSON 解析失败静默吞异常。本分支在不改动旧行为的前提下，新增「任意值」类型与配套节点解决上述能力缺口。

## 2. 核心设计：PinAny（任意值针脚）

- 值模型：`{ payload, meta }` 装箱，`payload` 为任意 `PinBase`（字符串/数字/布尔/列表/字典/图片…，可递归嵌套），类型标签由 payload 派生。
- 声明为**非 DYNAMIC**：旧强类型针脚按既有严格类匹配拒绝直连，保证「任意值进旧节点必须经拆箱」。
- `linkFromAble = pin instanceof PinObject`：任意值类型（含跨组列表/字典）可直接连入新节点，运行期按**自动装箱**语义包装；执行针脚等非值类型仍拒绝。
- `linkToAble` 仅放行 PinAny。
- 序列化复用既有 `PinBase` 多态机制（type/subType 标签 + 反射构造），meta 为派生数据、反序列化时重算。
- `customAble=true`：变量、列表元素、字典键值、自定义针脚的类型清单均可选「任意值」。

## 3. 六节点（添加节点 → 字典分组；JSON 安全版在字符串分组）

| 节点 | 职责 | 失败行为 |
|---|---|---|
| 装箱 | 旧值 → 任意值 | — |
| 拆箱 | 任意值 → 目标类型（7 种下拉），编辑期同步结果针脚类型 | 类型不符走 failPin + errorPin；目标字符串时宽容转换 |
| 值类型判断 | 输出 `STRING/NUMBER/BOOLEAN/LIST/MAP/IMAGE/OBJECT` | 旧值直连按自动装箱处理 |
| 取字段/取下标 | 字典按键、列表按下标（任意值输入先解包） | 缺键/越界/非容器走 failPin |
| 组对象 | 字典写键值/列表追加，基对象副本上修改（任意值输入先解包） | 异常走 failPin |
| JSON解析(安全) | 对象/数组根全量递归解析 | 解析失败走 failPin + errorPin，不吞异常 |

**已知边界**：上游 `PinString.linkFromAble` 本就宽松，任意值可连入字符串针脚，建议仍经拆箱；JSON 数组根时结果针脚实际值为列表（声明与旧版一致），请接动态节点而非旧字典节点。

## 4. 兼容性

- 旧文件改动仅限注册表增量行（`PinType/PinInfo/ActionType/ActionInfo/ActionMap` + 字符串资源），`PinList/PinMap` 及旧容器节点零改动。
- pins 声明顺序固定，`reAddPins` 按序匹配，无迁移。
- 枚举按 name 序列化，新增枚举值不影响旧任务反序列化。
- 另含独立 `fix(ui)` commit：修复基线 `CardLayoutView.newCard` 调用不存在的 `getActionInfo(Action)`/`getExtensionKey()` 导致的编译失败（上游既有问题，与本功能无关，单独提交便于摘取）。

## 5. 使用指引（简版）

1. **任意值变量**：变量卡类型按钮选「任意值」→ 赋值节点可塞任意类型；⚠️ 已有数据的容器切类型会清空内容，先备份。
2. **混合列表/字典**：列表/字典的元素（值）类型选「任意值」→ 多维、混装。
3. **新旧互通**：旧值 →（装箱/直连）→ 新节点；任意值 → 拆箱 → 旧节点。
4. **失败分支建议常接**（如记录日志），便于定位运行时类型错误。
